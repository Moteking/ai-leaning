## サービス名案：**おやつ（OyaTsu）**

> 「親に、つながる。親に、届く。」
> （「親」+「通」で「おやつ」。おやつのように日常的に親を想う習慣をつくる）

**「親のためにできること」の全てが、ここで選べる。**

Amazonは「自分のための買い物」の入り口。

## 2. なぜ「親孝行専門」が成立するのか

### 市場規模

```
対象人口:
- 65歳以上の親を持つ子供世代（35-65歳）: 約3,500万人
- このうち「親に何かしたいが、何をすればいいかわからない」: 推定60%

金額感:
- 母の日・父の日ギフト市場: 約3,000億円/年
- 親への旅行プレゼント: 推定2,000億円/年
- 実家のリフォーム: 約1.5兆円/年（親世代が住む築30年以上の住宅）
- 親の介護関連サービス: 約10兆円/年
- 親の見守りサービス: 約500億円/年

→ 合計: 数兆円規模の「親のために使うお金」が存在
→ しかし、それを横断的に扱う専門サイトは存在しない
```

### 既存サービスの問題

```
Amazon / 楽天      → 「モノ」しか送れない。体験や安心は売っていない
JTB / HIS          → 旅行だけ。「親に合う旅行」の提案力が弱い
リフォーム会社      → 自分で探すのが大変。親の家に合うかわからない
見守りサービス      → 「監視されている感」が強く、親が嫌がる
ギフトEC            → 汎用的すぎる。「親」に最適化されていない

→ 全部バラバラ。「親孝行」というユースケースで統合されたサービスがない
```

## 3. ターゲットユーザー

### 購入者（子供側）

| セグメント | 年齢 | 親の状態 | 典型的な気持ち |
|-----------|------|---------|--------------|
| 遠方に住む社会人 | 30-40代 | 元気だがあまり会えない | 「帰省できない罪悪感」 |
| 結婚して家庭を持った層 | 35-50代 | やや衰えが見え始める | 「そろそろ何かしてあげたい」 |
| 親の老いを実感した層 | 45-55代 | 病気や入院を経験 | 「今のうちにできることをしたい」 |
| 兄弟で費用を分担したい層 | 全年齢 | — | 「兄弟で割り勘したい」 |

### 受取者（親側）

| セグメント | 特徴 | 喜ぶもの |
|-----------|------|---------|
| アクティブシニア（65-74歳） | まだ元気。旅行・趣味が楽しめる | 体験ギフト、旅行、趣味の道具 |
| 前期高齢者（75-84歳） | 体力低下。外出が減る | 家事代行、食事宅配、リフォーム |
| 後期高齢者（85歳〜） | 介護が必要になりつつある | 見守り、介護用品、訪問サービス |

### サブスクの解約抑止力

```
通常のサブスク:
→ 解約 = 「自分が損する」だけ → 気軽に解約

おやつのサブスク:
→ 解約 = 「親への贈り物をやめる」→ 罪悪感で解約しにくい
→ 解約率は通常のサブスクの1/3以下と予測

さらに:
→ 親が「来月は何が届くかな」と楽しみにし始める
→ 親から「今月のおやつ美味しかったよ」と連絡が来る
→ 「やめられない」が自然に生まれる
```

## 7. AIレコメンドエンジン設計

### 入力データ

```
[親の情報]
├── 基本属性（年齢、性別、居住地、同居状況）
├── 健康状態（自己申告 + 見守りデータ連携）
├── 趣味・嗜好
├── 過去に贈ったもの＋親の反応
└── 季節・イベント（誕生日、敬老の日、母の日等）

[子供の情報]
├── 予算（1回あたり / 月あたり）
├── 贈り方の好み（サプライズ？ / 一緒に体験？）
├── 過去の購入履歴
└── 兄弟の有無・割り勘意向
```

### レコメンドロジック

```
Layer 1: 基本フィルタ
→ 健康状態に合わないものを除外（膝が悪い → ハイキング除外）
→ 予算外のものを除外
→ 過去3ヶ月以内に似たものを贈っていれば除外

Layer 2: 季節・イベント連動
→ 3月 → 花のギフト、春の旅行
→ 夏 → 冷感グッズ、そうめんセット
→ 誕生日1ヶ月前 → 特別な体験ギフトを優先

Layer 3: パーソナライズ
→ 「園芸好き」→ 季節の苗セット、園芸ツール
→ 「料理好き」→ 産直食材、調理家電
→ 「外出好き」→ 旅行、食事券
→ 「インドア」→ 書籍、ストリーミング契約代行

Layer 4: コラボレーティブフィルタ
→ 「72歳/女性/園芸好き」の他の親に人気のギフトを推薦
→ 「この親に贈った人は、こんなものも贈っています」

Layer 5: サプライズ要素
→ 月に1回、予想外のジャンルから1品を混ぜる
→ 「お父さんに文房具？」→ 実は大人の塗り絵セットが好評
```

```

→ ギフトで入口を作り、旅行→リフォーム→見守りへとアップセル
```

### 8.3 収益フローの全体像

```
ユーザーの人生ステージに合わせてLTVが自然に成長する:

[30代] 親が元気 → ギフト中心（年¥20,000）
          ↓
[40代] 親が衰え始める → 旅行 + 健康サービス追加（年¥80,000）
          ↓
[50代] 親の介護が始まる → リフォーム + 見守り + 介護サービス（年¥200,000+）
          ↓
[60代] 終活 → 相続相談 + 生前整理（年¥100,000）

→ 1ユーザーと30年の関係を築ける可能性がある
→ これがAmazonやギフトECにはない「親孝行専門」の強み
```

## 10. 差別化ポイント（他のECサイトにない機能）

### 10.1 「手紙ジェネレーター」

```
親に贈り物をする時、最大の障壁は「何て書けばいいか」。
AIがユーザーの気持ちを汲み取り、手紙の下書きを生成する。

入力: 「最近帰省できてなくて申し訳ない。元気でいてほしい」
      ↓
出力: 「お母さんへ
      なかなか帰れなくてごめんね。
      でもいつもお母さんのこと考えてるよ。
      体に気をつけて、元気でいてね。
      今度帰った時、一緒にご飯食べよう。」
      ↓
ユーザーが編集 → 手書き風フォントで印刷 → ギフトに同封
```

### 10.2 「親の反応レポート」

```
贈った後のフォローアップ:

ギフト到着後、親にSMSで簡単なアンケートを送信（任意）:
「息子さん/娘さんから届きました！嬉しさを教えてください」
→ 😊😊😊😊😊 （5段階タップ）
→ 一言感想（任意）: 「みかん美味しかった！ありがとう」

子供側に通知:
「お母さんからの反応が届きました！」
→ 😊😊😊😊😊
→ 「みかん美味しかった！ありがとう」

→ この「親からの反応」がリピート購入の最強トリガーになる
```

### 10.3 「親孝行カレンダー」

```
年間の親孝行タイミングを自動リマインド:

1月: お正月（帰省できなかった場合のフォロー提案）
2月: ——
3月: お母さんの誕生日 ← 自動登録
4月: ——
5月: 母の日
6月: 父の日
7月: お中元
8月: お盆
9月: 敬老の日
10月: お父さんの誕生日 ← 自動登録
11月: ——
12月: お歳暮 / クリスマス

各イベント2週間前に:
「お母さんの誕生日まであと14日。去年はお花を贈りました。
 今年は○○はいかがですか？」
```

### 10.4 兄弟連携機能

```
「贈り物がかぶった」を防止する機能:

兄弟をグループに招待 →
→ 誰が何を贈ったか/贈る予定かが共有される
→ 「兄が母の日にお花を予約済み」が見える
→ 自分は別のものを選べる

割り勘機能:
→ 高額な贈り物（旅行、リフォーム）を兄弟で分担
→ LINE/PayPayで簡単に請求・支払い
```

## 12. 競合との差別化

```
サービス       何を提供        おやつとの違い
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Amazon         何でも買える     「親孝行」という文脈がない
                               → おやつは「親のため」に全てが最適化

楽天           ギフト特集あり   ギフト以外（旅行・リフォーム）がない
                               → おやつは「モノ以外」も全部ある

JTB            旅行             旅行だけ。「親向け」のフィルタがない
                               → おやつは親の健康状態に合わせた旅行提案

ギフトモール    ギフト特化       「誰に」ではなく「何を」で探すUI
                               → おやつは「親」に完全特化

ホームプロ      リフォーム見積もり 子供が親の代わりに相談する導線がない
                               → おやつは「子供→親」の文脈で設計
```
