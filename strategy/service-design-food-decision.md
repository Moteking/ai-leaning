# 「何食べよう」食の意思決定OS — サービス設計書

## サービス名案：**メシパス（MeshiPass）**

> 「今日のご飯、3秒で決まる」

---

## 1. コンセプト

毎日1,000万人以上が抱える「今夜何食べよう」を、
**自炊・デリバリー・外食の3択**で毎日解決するアプリ。

自分では料理しない。配達しない。店を持たない。
**「食の意思決定」という1日3回の入り口だけを押さえる。**

---

## 2. ターゲットユーザー

### メインターゲット
| セグメント | 特徴 | ペイン |
|-----------|------|-------|
| 共働き夫婦（30-40代） | 時間がない、疲れている | 「考える余裕がない。でも健康も気になる」 |
| 一人暮らし（20-30代） | 自炊スキル低、外食多い | 「毎日コンビニ飯。でも変えたい」 |
| 子育て世帯 | 子供のアレルギー・栄養管理 | 「子供に何食べさせればいいか不安」 |

### サブターゲット
- ダイエット/筋トレ中の人（マクロ管理が面倒）
- 高齢者世帯（買い物が大変、栄養が偏りがち）

## 3. ユーザー体験（UX）フロー

### 初回セットアップ（3分で完了）

```
Step 1: 基本情報
  → 世帯人数、年齢構成
  → アレルギー・嫌いな食材
  → 宗教的制約（ハラル、ヴィーガンなど）

Step 2: 食のスタイル
  → 自炊頻度（毎日/週3/ほぼしない）
  → 予算（1食あたり: 〜500円 / 〜1,000円 / 気にしない）
  → 健康目標（ダイエット/筋トレ/特になし/持病管理）

Step 3: 連携サービス
  → 近所のスーパー選択（位置情報から自動提案）
  → デリバリーアプリ連携（UberEats/出前館/menu）
  → 決済手段の登録
```

### 毎日の体験

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  🕐 17:00  プッシュ通知

  「今夜のメシパス、届きました」
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌─────────────────────────────┐
  │  A. 自炊する（25分）          │
  │  鶏むね肉のレモン焼き         │
  │  材料費: 680円（2人前）        │
  │  [OKストアに在庫あり]          │
  │  → タップで買い物リスト生成    │
  ├─────────────────────────────┤
  │  B. デリバリー（30分で届く）   │
  │  松屋 牛めし + サラダセット    │
  │  890円（UberEats配達料込み）   │
  │  → タップで注文完了            │
  ├─────────────────────────────┤
  │  C. 外食する                   │
  │  鳥貴族 徒歩8分 空席あり       │
  │  2人で約3,000円               │
  │  → タップで予約完了            │
  └─────────────────────────────┘

  [どれも気分じゃない → シャッフル🔀]
```

### 重要な設計ポイント

1. **3択に絞る** — 選択肢が多すぎると決められない。「松竹梅」の3択が最適
2. **ワンタップで完了** — 選んだ瞬間に注文/買い物リスト/予約が完了する
3. **17時に届く** — 「何食べよう」と考え始める瞬間に先回り
4. **シャッフルは1回だけ** — 無限にシャッフルすると選べなくなる。2回目は「おまかせ」ボタン

## 4. AIレコメンドエンジン設計

### 入力データ

```
[ユーザーデータ]
├── 基本属性（年齢、世帯、アレルギー）
├── 食事履歴（過去の選択ログ）
├── 健康データ（体重推移、歩数、ウェアラブル連携）
├── 気分データ（天気、曜日、残業有無）
└── 季節・イベント（クリスマス、猛暑日、給料日前）

[外部データ]
├── 近隣スーパーの当日特売情報（API/スクレイピング）
├── デリバリーサービスのリアルタイム配達時間
├── 飲食店の空席状況（ホットペッパー/食べログAPI）
├── 天気予報（雨の日は外食提案を下げる）
└── 栄養バランス（直近3日間の食事から不足栄養素を計算）
```

### レコメンドロジック

```
優先度1: 栄養バランス
  → 直近3日で野菜不足 → サラダ系を優先
  → 直近3日で炭水化物過多 → 低糖質メニューを優先

優先度2: 予算コントロール
  → 今月の食費が予算上限に近い → 自炊を優先
  → 給料日直後 → 外食の予算枠を拡大

優先度3: 行動パターン
  → 金曜夜はデリバリー率が高い → デリバリーを上位に
  → 火曜は自炊率が高い → 自炊レシピの質を上げる
  → 雨の日 → 外食提案を消してデリバリーと自炊の2択に

優先度4: マンネリ防止
  → 同じメニューが3日以内に出ない
  → 2週間で同じ店を提案しない
  → 月1回「冒険メニュー」（普段選ばないジャンル）を混ぜる
```

### 6.3 広告モデル（食品メーカー向け）

```
例：キッコーマンが新しい「麺つゆ」をプロモーションしたい場合

→ 「今夜の自炊提案」に、その麺つゆを使ったレシピを自然に混ぜる
→ ユーザーが選択した場合のみ、キッコーマンに課金
→ CPAモデル: 1選択あたり50-100円

ポイント:
- バナー広告ではなく「レシピの中に自然に溶け込む」ネイティブ広告
- ユーザーにとっても有益（新商品を知れる）なのでUXを壊さない
- 食品メーカーにとっては「実際に使ってもらえる」最強のプロモーション
```

## 7. データ戦略（=最大の参入障壁）

### 蓄積されるデータ

```
1日目:   「この人は金曜にデリバリーを頼む」
1週間後: 「和食が好き。辛いものは避ける」
1ヶ月後: 「給料日前は自炊率が上がる」
3ヶ月後: 「鶏肉好き、豚肉はたまに、牛肉は月1」
半年後:  「梅雨はさっぱり系、冬は鍋系を好む」
1年後:   「この人の食の好み、行動パターン、健康傾向の完全なプロファイル」
```

### なぜ後発が追いつけないか

```
ユーザーの1年分の食事データ = このアプリだけが持つ資産
→ 他のアプリに乗り換えても、データはゼロからスタート
→ レコメンド精度が圧倒的に違う
→ 結果、「もうこのアプリなしでは決められない」状態になる
```

## 9. 競合との差別化

```
サービス        何を提供        メシパスとの違い
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
クックパッド    レシピ検索      「作りたいもの」が決まっている人向け
                               → メシパスは「決まっていない人」向け

UberEats        デリバリー      デリバリーのみ。自炊・外食という選択肢がない
                               → メシパスは全選択肢を横断

あすけん        食事記録        記録するだけ。「で、何食べればいい？」に答えない
                               → メシパスは「提案→実行」まで完結

Oisix           食材宅配        定期便。「今日」のリアルタイム性がない
                               → メシパスは毎日リアルタイムで最適化

ChatGPT         AI献立相談      毎日聞くのが面倒。注文・予約まで繋がらない
                               → メシパスは提案→注文がワンタップ
```
